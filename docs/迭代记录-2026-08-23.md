### 二、本期调测经验（V0.4.0 增量）

- **问题**：`WeeklyScreen.kt` 缺 `import androidx.compose.ui.graphics.Color` 与 `androidx.compose.ui.unit.sp`，但已用 `Color.Transparent` / `Color.White.copy(...)` / `9.sp`。
  **解决**：补两个 import。

- **问题**：`WeeklyScreen.kt` 的 `FourKpiGrid` 写了 `padding(horizontal = 20.dp, horizontal = 20.dp)`，Kotlin 拒绝同 named param 重复。
  **解决**：删一个，保留 `padding(horizontal = 20.dp)`。

- **问题**：`RestScreen.kt` 仍调用 `StatusBar()` composable，但 `StatusBar.kt` 在 V0.1.0 已被清成 deprecation 占位，导致 `Unresolved reference: StatusBar`。
  **解决**：删 `StatusBar()` 调用 + 删对应 import。

- **决策**：Running 屏永远深色背景（即使系统是 light theme），理由是聚焦模式下任何亮色都会破坏沉浸感，与 prototype 视觉完全一致。

- **决策**：底部图标按钮 + 圆环手势并存，按钮是 affordance（让用户看到能力），手势是底层快捷控制，prototype 就是这样设计的。

- **决策**：Streak 卡月度目标 20 天写死常量，不接 DailyGoalDao 的字段，避免和已有「每日目标」概念冲突。

## 三、本期调测经验

### 调试经验

- **问题**：首次编译报 `Too many arguments for HistoryViewModel`
  **解决**：精简 `HistoryViewModel` 时删了 `SettingsRepository` 参数但漏改 `FlowViewModelFactory.kt`，对齐构造函数签名。

- **问题**：`Unresolved reference 'Row' / 'width'` 编译报错
  **解决**：清理各屏 `private val Unused = ...` 占位行时连带删了 `layout` 包的 import，逐一补回 `import androidx.compose.foundation.layout.{Row, width}`。

- **问题**：`Unresolved reference 'flow'` 报错
  **解决**：`FlowNavHost.kt` 写错了包名 `com.liuflow.app.ui.flow.FocusScreen`，正确应为 `com.liuflow.app.ui.focus.FocusScreen`。

- **问题**：`Condition type mismatch: inferred type is 'PointerInputChange?' but 'Boolean' was expected`
  **解决**：`waitForUpOrCancellation()` 返回 `PointerInputChange?`（取消时为 null），把 `released && ...` 改成 `released != null && ...` 区分正常释放与手势取消。

- **问题**：原 FAB 在 edge-to-edge 模式下被系统底部导航条遮挡，模拟器上看不到
  **解决**：用圆环接管开始/暂停/停止，符合 PRD「极致克制」原则，同时天然支持长按扫光手势，无须额外控件。

- **问题**：AS 内置 AOSP 镜像没有 Google Play，但需要确保 App 仍能完整运行
  **解决**：确认 `AndroidManifest.xml` 未声明任何 GMS 依赖，纯 Room + DataStore 全本地化，AOSP 镜像直接装即可跑。

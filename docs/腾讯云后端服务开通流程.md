# 腾讯云后端服务开通流程（V0.2.0 流 Flow）

> 目标读者：V0.2.0 PRD 的实施者 / Android 客户端开发者
> 核心思路：**不写云函数、不部署后端应用**，用腾讯云 CloudBase 的「内置身份认证 + PostgreSQL + RLS 行级权限」三件套搞定一切
> 配套文档：[`docs/prd_v0.2.0.md`](./prd_v0.2.0.md)

---

## TL;DR

| 项 | 选型 | 备注 |
|---|---|---|
| **短信下发** | CloudBase 内置短信登录（不直接买腾讯云 SMS 包） | 首月 100 条免费，单日上限 30 条 |
| **身份认证** | CloudBase Auth（v2） | 0 代码，3 行 SDK 调用 |
| **数据库** | CloudBase PostgreSQL | 对齐 Supabase 心智 |
| **权限隔离** | PostgreSQL RLS（行级安全策略） | 0 代码，5 张表 × 4 行 SQL |
| **云函数** | **不部署** | V0.2.0 PRD 的 6 个云函数全部砍掉 |
| **总耗时** | 30 - 60 分钟 | 含实名认证等待 |

**和 V0.2.0 PRD 的差异**：原 PRD §13.6 列了 6 个云函数（sendCode / verifyLogin / syncSession / syncSettings / getUserData / batchMigrate）。本流程把这 6 个全部砍掉，**全部能力由 CloudBase Auth + PostgreSQL + RLS 直接覆盖**。客户端 SDK 直接调 HTTP API 即可，不写一行后端代码。

## 0. 整体架构

```
┌──────────────────┐         ┌──────────────────────┐
│ Android 客户端    │         │ CloudBase（无需运维） │
│ (Kotlin)         │         │                      │
│                  │  HTTPS  │ ┌──────────────────┐ │
│ ┌──────────────┐ │ ──────→ │ │ Auth（内置）     │ │
│ │ 登录页 UI    │ │         │ │ · 手机号+验证码  │ │
│ │ 输入手机号    │ │         │ │ · JWT 颁发       │ │
│ └──────────────┘ │         │ │ · 自动续期       │ │
│ ┌──────────────┐ │         │ └──────────────────┘ │
│ │ SDK 直调 API │ │         │ ┌──────────────────┐ │
│ │ 读写数据     │ │ ←────── │ │ PostgreSQL       │ │
│ │ 自动带 RLS   │ │  响应   │ │ · 5 张业务表     │ │
│ └──────────────┘ │         │ │ · RLS 策略隔离   │ │
│                  │         │ │ · 客户端 0 代码  │ │
└──────────────────┘         │ └──────────────────┘ │
                             │ ┌──────────────────┐ │
                             │ │ 短信下发（自动） │ │
                             │ │ 走腾讯云 SMS     │ │
                             │ └──────────────────┘ │
                             └──────────────────────┘
```

**零部署** = 没有云函数、没有 ECS、没有负载均衡。所有服务都是 CloudBase 托管的，开通即用。

## Step 2. 创建 CloudBase 环境（3 分钟）

### 2.1 开通 CloudBase

地址：https://console.cloud.tencent.com/tcb

1. 点击「立即开通」
2. 选择计费模式：**个人版 ¥19.9/月**（独立开发者推荐）或免费版（学习验证）
3. 选择地域：**必须选「上海」**（短信登录仅支持上海地域）
4. 选择数据库模式：**PostgreSQL 模式**（PostgREST + RLS，2026 年新模式）
5. 等待环境创建（约 1-2 分钟）

> ⚠️ **关键决策**：地域**必须选上海**。广州 / 北京 / 新加坡都不支持短信登录。环境创建后地域**无法修改**，选错只能新建环境。

### 2.2 记录环境信息

环境创建完成后，记录以下信息（后续步骤都要用）：

| 名称 | 用途 | 在哪里找 |
|------|------|---------|
| **环境 ID** | 客户端 SDK 初始化用 | 控制台 → 云开发 → 环境卡片顶部 |
| **Publishable Key** | 前端使用，对应 anon 角色 | 控制台 → 云开发 → 环境 → API 密钥管理 |
| **API Key（可选）** | 后端使用，对应 service_role | 同上，**严禁暴露给前端** |

Publishable Key 形如：`pkey_xxxxxxxxxxxxxxxxxxxxxxxx`

## Step 4. 创建数据表（5 分钟）

### 4.1 打开 SQL 编辑器

控制台 → 云开发 → 你的环境 → 数据库 → SQL 编辑器

### 4.2 一键执行建表 SQL

把下面整段 SQL **复制粘贴**到 SQL 编辑器，点「执行」：

```sql
-- ============================================
-- 1. 专注记录表（核心表，PRIVATE 权限）
-- ============================================
CREATE TABLE public.sessions (
  id varchar(40) PRIMARY KEY,
  owner_id varchar(64) NOT NULL DEFAULT (current_setting('request.jwt.claims', true)::json->>'sub'),
  task text,
  category varchar(20),
  planned_duration int,
  actual_duration int,
  status varchar(20),
  started_at timestamptz,
  ended_at timestamptz,
  hour int,
  weekday int,
  date varchar(10),
  last_modified_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_sessions_owner_date ON public.sessions(owner_id, date);
CREATE INDEX idx_sessions_owner_started ON public.sessions(owner_id, started_at DESC);

-- ============================================
-- 2. 每日目标表
-- ============================================
CREATE TABLE public.daily_goals (
  owner_id varchar(64) NOT NULL DEFAULT (current_setting('request.jwt.claims', true)::json->>'sub'),
  date varchar(10) NOT NULL,
  target int NOT NULL,
  last_modified_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (owner_id, date)
);

-- ============================================
-- 3. 个人设置表
-- ============================================
CREATE TABLE public.settings (
  owner_id varchar(64) PRIMARY KEY DEFAULT (current_setting('request.jwt.claims', true)::json->>'sub'),
  theme varchar(20),
  dark_mode varchar(20),
  default_focus_minutes int,
  default_rest_minutes int,
  sound_enabled boolean,
  vibration_enabled boolean,
  last_modified_at timestamptz
);
```

执行成功后，会显示「Query returned successfully」。

> 💡 **`owner_id` 是 CloudBase RLS 的标准字段名**，默认从 JWT 读取当前用户 ID。客户端无需传入，从源头杜绝身份伪造。

### 4.3 验证

点数据库左侧的「表」标签，应该看到 3 张表：
- sessions
- daily_goals
- settings

## Step 5. 配置 RLS 行级安全（5 分钟，0 代码）

> 这一步是整个后端架构的**灵魂**。配置完成后，客户端自动按"只读自己"工作，再也不用写后端鉴权代码。

### 5.1 创建辅助函数（首次配置时执行一次）

```sql
-- 抽象函数：返回当前登录用户 ID（从 JWT claims 解析）
CREATE OR REPLACE FUNCTION auth.uid() RETURNS text
LANGUAGE SQL STABLE AS $$
  SELECT current_setting('request.jwt.claims', true)::json->>'sub'
$$;

-- 抽象函数：返回当前角色
CREATE OR REPLACE FUNCTION auth.role() RETURNS text
LANGUAGE SQL STABLE AS $$
  SELECT current_setting('request.jwt.claims', true)::json->>'role'
$$;
```

### 5.2 启用 RLS + 表级授权

```sql
-- 启用 RLS
ALTER TABLE public.sessions ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.daily_goals ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.settings ENABLE ROW LEVEL SECURITY;

-- 表级 GRANT：登录用户可读写，匿名用户无权限
GRANT SELECT, INSERT, UPDATE, DELETE ON public.sessions TO authenticated;
GRANT USAGE, SELECT ON SEQUENCE public.sessions_id_seq TO authenticated;
GRANT ALL ON public.sessions TO service_role;
GRANT USAGE, SELECT ON SEQUENCE public.sessions_id_seq TO service_role;

GRANT SELECT, INSERT, UPDATE, DELETE ON public.daily_goals TO authenticated;
GRANT ALL ON public.daily_goals TO service_role;

GRANT SELECT, INSERT, UPDATE, DELETE ON public.settings TO authenticated;
GRANT ALL ON public.settings TO service_role;
```

### 5.3 写行级 Policy（4 套模板，每个表照搬）

#### 5.3.1 sessions 表（PRIVATE 模式：仅自己可读写）

```sql
-- SELECT：只能读自己的
CREATE POLICY sessions_select_own ON public.sessions
  FOR SELECT TO authenticated
  USING (owner_id = (select auth.uid()));

-- INSERT：只能插入 owner_id = 自己的
CREATE POLICY sessions_insert_own ON public.sessions
  FOR INSERT TO authenticated
  WITH CHECK (owner_id = (select auth.uid()));

-- UPDATE：只能改自己的，且不能改 owner_id
CREATE POLICY sessions_update_own ON public.sessions
  FOR UPDATE TO authenticated
  USING (owner_id = (select auth.uid()))
  WITH CHECK (owner_id = (select auth.uid()));

-- DELETE：只能删自己的
CREATE POLICY sessions_delete_own ON public.sessions
  FOR DELETE TO authenticated
  USING (owner_id = (select auth.uid()));
```

#### 5.3.2 daily_goals 表（同上）

```sql
CREATE POLICY goals_select_own ON public.daily_goals
  FOR SELECT TO authenticated
  USING (owner_id = (select auth.uid()));
CREATE POLICY goals_insert_own ON public.daily_goals

CREATE POLICY goals_update_own ON public.daily_goals
```

### 6.2 创建 CloudBase 客户端

新建文件 `app/src/main/java/com/liuflow/app/cloud/CloudBaseClient.kt`：

```kotlin
package com.liuflow.app.cloud

import android.content.Context
import com.google.gson.Gson
import com.google.gson.reflect.TypeToken
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import okhttp3.MediaType.Companion.toMediaType
import okhttp3.OkHttpClient
import okhttp3.Request
import okhttp3.RequestBody.Companion.toRequestBody
import java.util.concurrent.TimeUnit

/**
 * CloudBase 客户端（极简封装）
 * 配套 V0.2.0 PRD §13.4 数据表 + §5 RLS
 */
class CloudBaseClient(
    private val context: Context,
    private val envId: String,
    private val publishableKey: String
) {
    private val baseUrl = "https://$envId.api.tcloudbasegateway.com"
    private val http = OkHttpClient.Builder()
        .connectTimeout(10, TimeUnit.SECONDS)
        .readTimeout(15, TimeUnit.SECONDS)
        .build()
    private val gson = Gson()

    @Volatile
    var accessToken: String? = null
        private set

    fun updateAccessToken(token: String) {
        accessToken = token
    }

    /**
     * 通用 HTTP 请求
     */
    suspend fun <T> request(
        method: String,
        path: String,
        body: Map<String, Any>? = null,
        typeToken: TypeToken<T>? = null
    ): T? = withContext(Dispatchers.IO) {
        val url = "$baseUrl$path"
        val requestBody = body?.let { gson.toJson(it).toRequestBody("application/json".toMediaType()) }

        val builder = Request.Builder().url(url)
        when (method.uppercase()) {
            "GET" -> builder.get()
            "POST" -> builder.post(requestBody ?: "".toRequestBody("application/json".toMediaType()))
            "PATCH" -> builder.patch(requestBody ?: "".toRequestBody("application/json".toMediaType()))
            "DELETE" -> builder.delete(requestBody)
            else -> throw IllegalArgumentException("Unsupported method: $method")
        }

        // 注入 Publishable Key
        builder.header("X-CloudBase-Env", envId)
        // 注入 JWT（如果已登录）
        accessToken?.let { builder.header("Authorization", "Bearer $it") }

        try {
            val response = http.newCall(builder.build()).execute()
            val responseText = response.body?.string() ?: return@withContext null
            if (!response.isSuccessful) {
                android.util.Log.e("CloudBase", "HTTP ${response.code}: $responseText")
                return@withContext null
            }
            if (typeToken == null) {
                @Suppress("UNCHECKED_CAST")
                return@withContext gson.fromJson(responseText, Map::class.java) as? T
            }
            gson.fromJson(responseText, typeToken.type)
        } catch (e: Exception) {
            android.util.Log.e("CloudBase", "Request failed: ${e.message}", e)
            null
        }
    }
}
```

### 6.3 实现登录

新建 `LoginRepository.kt`：

```kotlin
package com.liuflow.app.cloud

import com.google.gson.reflect.TypeToken

class LoginRepository(private val cloudbase: CloudBaseClient) {

    // ========== Step 1：发送验证码 ==========
    suspend fun sendCode(phone: String): String? {
        val formattedPhone = if (phone.startsWith("+86")) phone else "+86$phone"
        val result = cloudbase.request<Map<String, Any>>(
            method = "POST",
            path = "/auth/v1/verification",
            body = mapOf(
                "phone_number" to formattedPhone,
                "target" to "ANY"  // 任何用户都可以发（首次登录即注册）
            ),
            typeToken = object : TypeToken<Map<String, Any>>() {}
        )
        return result?.get("verification_id") as? String
    }

    // ========== Step 2：验证 + 登录 ==========
    suspend fun loginWithCode(phone: String, verificationId: String, code: String): Boolean {
        // 验证验证码
        val verifyResult = cloudbase.request<Map<String, Any>>(
            method = "POST",
            path = "/auth/v1/verification/verify",
            body = mapOf(
                "verification_id" to verificationId,
                "verification_code" to code
            ),
            typeToken = object : TypeToken<Map<String, Any>>() {}
        ) ?: return false

        val verificationToken = verifyResult["verification_token"] as? String ?: return false

        // 用 verification_token 登录（自动注册）
        val loginResult = cloudbase.request<Map<String, Any>>(
            method = "POST",
            path = "/auth/v1/signin",
            body = mapOf(
                "phone_number" to if (phone.startsWith("+86")) phone else "+86$phone",
                "verification_token" to verificationToken
            ),
            typeToken = object : TypeToken<Map<String, Any>>() {}
        ) ?: return false

        // 拿到 access_token，写入客户端
        val accessToken = loginResult["access_token"] as? String ?: return false
        cloudbase.updateAccessToken(accessToken)
        return true
    }

    // ========== 退出登录 ==========
    suspend fun logout() {
        cloudbase.updateAccessToken("")
    }
}
```

### 6.4 实现数据同步（替代 V0.2.0 PRD §13.6 的 6 个云函数）

新建 `SyncRepository.kt`：

```kotlin
package com.liuflow.app.cloud

import com.google.gson.reflect.TypeToken

class SyncRepository(private val cloudbase: CloudBaseClient) {

    /**
     * 上传一条 Session 记录
     * RLS 自动校验：只能写 owner_id = 自己的
     */
    suspend fun uploadSession(session: Map<String, Any>): Boolean {
        val result = cloudbase.request<Map<String, Any>>(
            method = "POST",
            path = "/v1/rdb/rest/sessions",
            body = session,
            typeToken = object : TypeToken<Map<String, Any>>() {}
        )
        return result != null
    }

    /**
     * 批量上传 Sessions（V0.1.0 → V0.2.0 迁移用）
     */
    suspend fun batchUploadSessions(sessions: List<Map<String, Any>>): Boolean {
        val result = cloudbase.request<Map<String, Any>>(
            method = "POST",
            path = "/v1/rdb/rest/sessions",
            body = sessions,
            typeToken = object : TypeToken<Map<String, Any>>() {}
        )
        return result != null
    }

    /**
     * 拉取自己的所有 Sessions
     * RLS 自动过滤：只返回 owner_id = 自己的
     */
    suspend fun fetchAllSessions(): List<Map<String, Any>> {
        val result = cloudbase.request<List<Map<String, Any>>>(
            method = "GET",
            path = "/v1/rdb/rest/sessions?select=*&order=started_at.desc",
            typeToken = object : TypeToken<List<Map<String, Any>>>() {}
        )
        return result ?: emptyList()
    }

    /**
     * 上传 / 更新 Settings（一行一用户）
     */
    suspend fun upsertSettings(settings: Map<String, Any>): Boolean {
        val result = cloudbase.request<Map<String, Any>>(
            method = "POST",
            path = "/v1/rdb/rest/settings",
            body = settings,
            typeToken = object : TypeToken<Map<String, Any>>() {}
        )
        return result != null
    }

    /**
     * 拉取自己的 Settings
     */
    suspend fun fetchSettings(): Map<String, Any>? {
        val result = cloudbase.request<List<Map<String, Any>>>(
            method = "GET",
            path = "/v1/rdb/rest/settings?select=*&limit=1",
            typeToken = object : TypeToken<List<Map<String, Any>>>() {}
        )
        return result?.firstOrNull()
    }
}
```

| 1 | 登录页输入手机号 `13800000000`，点「获取验证码」 | 1 秒内收到短信 |
| 2 | 输入收到的 6 位验证码，点「登录」 | 自动进入主屏，accessToken 写入内存 |
| 3 | 完成一次专注 | `sessions` 表新增一条记录，`owner_id` = 自己的 uid |
| 4 | 退出登录 | accessToken 清空，回到登录页 |
| 5 | 重新登录（同一手机号） | 数据完整恢复（RLS 自动过滤） |
| 6 | 用另一台手机登录（不同手机号） | 看不到第一台手机的数据（RLS 隔离生效） |
| 7 | 直接调用 REST API 查 `?owner_id=eq.other-user` | 仍然只返回自己的（RLS USING 子句过滤） |

### 7.3 SQL 控制台验证

```sql
-- 看最近 10 条 Sessions（RLS 会自动过滤）
SELECT * FROM public.sessions ORDER BY started_at DESC LIMIT 10;

-- 看 Settings
SELECT * FROM public.settings;
```

## 9. 常见问题

### Q1. 短信收不到？

排查顺序：
1. **手机号格式**：必须 `+86 13800000000`，加空格也可，但必须有 `+86`
2. **地域是否上海**：非上海地域**完全不支持**短信登录
3. **单日次数**：默认 30 条/天，超出后当天不再下发
4. **30 秒内重复发**：30 秒频率限制，等一下
5. **控制台测试短信**：身份认证 → 登录方式 → 短信验证码 → 「测试」按钮，看是否到

### Q2. 报错 401 Unauthorized？

- 检查 accessToken 是否正确写入 Header
- 检查 Publishable Key 是否正确（区分 Publishable Key 和 API Key）
- Token 过期：accessToken 有效期 2 小时，refreshToken 30 天。客户端要在过期前自动刷新

### Q3. RLS 配置后，service_role 也读不到数据？

- service_role 有 `BYPASSRLS` 权限，应该读得到
- 如果读不到：检查表名是否写错、是否在正确的 schema 下
- 调试 SQL：`SELECT auth.uid();` 应该返回当前用户的 sub

### Q4. 客户端能否直接调 REST API，不用 SDK？

可以。CloudBase 提供 PostgREST 接口：

```bash
# 1. 登录拿 access_token
curl -X POST "https://<envId>.api.tcloudbasegateway.com/auth/v1/signin" \
  -H "Content-Type: application/json" \
  -d '{"phone_number":"+8613800000000","verification_token":"..."}'

# 2. 查数据
curl "https://<envId>.api.tcloudbasegateway.com/v1/rdb/rest/sessions?select=*" \
  -H "Authorization: Bearer <access_token>"
```

### Q5. 怎么回滚（删除整个环境）？

控制台 → 云开发 → 环境 → 「销毁环境」→ 输入环境 ID 确认

注意：销毁后**所有数据不可恢复**。先导出备份。

### Q6. 数据库表结构升级（migration）怎么办？

CloudBase PostgreSQL 是标准 PostgreSQL，支持 `ALTER TABLE`。在 SQL 编辑器直接执行即可。V0.2.0 后续迭代加表加字段，用 `ALTER TABLE ... ADD COLUMN ...` 即可，无需特殊 migration 工具。

### Q7. 我不想用 RLS，想自己写后端逻辑？

可以。把「不部署后端应用」改成「用云函数」，具体方案：
- Step 5.3 的 4 套 Policy 全部删除
- 部署 6 个云函数（V0.2.0 PRD §13.6）
- 客户端不直连数据库，改为调云函数

但这违背了"简单点"的初衷，**不推荐**。

### Q8. ICP 备案怎么办？

如果 App 要上架国内应用市场，需要：
1. 腾讯云账号**企业认证**（个人认证无法备案）
2. ICP 备案（7-20 个工作日）：https://console.cloud.tencent.com/beian
3. 公安备案（额外 7 天）：https://beian.mps.gov.cn

如果只是**测试阶段不上架**，无需备案。

## 10. 撤销操作（应急回滚）

如果发现配置错了，按以下顺序回滚：

1. **删除 RLS 策略**：`DROP POLICY policy_name ON table_name;`
2. **关闭 RLS**：`ALTER TABLE table_name DISABLE ROW LEVEL SECURITY;`
3. **删除表**：`DROP TABLE table_name CASCADE;`
4. **关闭短信登录**：身份认证 → 登录方式 → 短信验证码 → 「关闭」
5. **销毁环境**：环境设置 → 销毁环境（**慎用，会删除所有数据**）

> 💡 建议每次配置变更前，先 SQL 备份：`CREATE TABLE xxx_backup AS SELECT * FROM xxx;`

### 字段名变更说明

V0.2.0 PRD 原表结构用 `uid` 字段，本流程改为 `owner_id`：

| V0.2.0 PRD | 本流程 | 理由 |
